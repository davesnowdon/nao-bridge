# Follow-up to the runtime and API plan re-review

The [review of c448b2f](https://github.com/davesnowdon/nao-bridge/pull/32#issuecomment-6684514533) predates the completed [container tests](runtime-experiment.md). Its implementation guidance remains useful. The following records how it affects the plan; it does not claim that planned functionality now exists.

| Review point | Assessment and plan change |
| --- | --- |
| Prefer a maintained base with the legacy SDK vendored in | Adopt after the [maintained-base experiment](inverted-packaging-experiment.md): all 21 native/ASGI/IPC checks pass on Ubuntu 24.04, together with the selected binary inventory and actual codec execution. Preserve the original Python 2 ABI in a private bundle; no old glibc or Flask is copied. Apple Silicon/robot validation remains open. A modern base does not update vendored legacy libraries. |
| Make the container the only recovery unit | Evaluate operational simplicity in 1A, keeping the current diagnostics-preserving contract until evidence supports changing it. Restart loses surviving API state and cannot establish that robot-side tasks stopped. Do not implement two recovery modes speculatively. |
| Use pipe EOF instead of a heartbeat; remove generation handshake/fencing | Do not adopt. A frozen process retains open descriptors; the passing frozen-API test depends on independent liveness detection. Generations also fence queued work during live session revocation, not just process restart. Any recovery choice still needs safe startup and explicit uncertain native outcomes. |
| Limit agent validation to generation, sequence, and TTL | Keep Python 2 small, but retain finite-value/range and service/handle checks at native dispatch. Share fixtures/capability snapshots; do not duplicate public defaults, profiles, or sequence/resource policy. |
| Decide where video/audio are acquired | Add to 1A with full 4B acceptance. Prefer bridge-side SDK acquisition; measure robot-side recording alternatives separately for each source. Retrieval credentials, robot disk quotas/cleanup, and interrupted transfers must be explicit if selected. The fixed-file experiment proves no real capture path. |
| Start with MJPEG | Adopt as the first video-format experiment, with one selected container and decoding/seeking tests. It still needs a JPEG encoder and muxer; the plan does not promise zero codec dependencies. Keep this work in bounded modern-process workers. |
| SQLite, incremental checksums, range downloads, one sample feed | Adopt. Specify file/metadata/quota crash reconciliation, immutable finalized content, checksum-derived ETags, authenticated byte ranges/If-Range, and recordings independent of SSE viewer backpressure. These are planned additions, not tested asset features. |
| Structured concurrency for sequences | Adopt as implementation guidance. Cancelling a Python task does not stop a NAOqi task; native cancellation, unknown outcomes, child history, and resource release remain explicit. |
| Per-step `on_failure: continue` | Defer. It needs semantics for failed/unknown children and parent outcome, and cannot release resources while native work may continue. Optional unsupported actions can be omitted during capability-aware construction/validation. Keep fail-fast behavior for the initial wire grammar. |
| Bounded `repeat: n` | Defer a new wire node. Expand finite steps under existing size/depth/duration limits; a convenience builder need not enlarge the language-neutral protocol. |
| Resource/duration preview and child-operation filtering | Adopt. Validation returns resource usage/timing estimates with unknown values explicit; whole-run reservations remain. `GET /operations?parent_id=` lists authorized direct children with normal pagination/history rules. |
| Hold via measured angles and `setAngles(..., 1.0)` | Add the measured-angle replacement mechanism to the 2A hardware experiment. Neither the local test nor the native API documentation establishes a verified physical hold. Measure timing/overshoot and speed fraction; do not select maximum speed by assumption. |
| Rename `autonomy/profile_applications` | Adopt `autonomy/profile_runs`; the Python helper remains `.apply(...)`. |

Recordings/assets and server-side parallel sequences remain in scope. HTTP/SSE and modern Python remain the chosen direction. The measured results support those choices on Linux amd64; the maintained-base comparison now selects Ubuntu 24.04. Physical robot tests, Apple Silicon, and production supervision/reconciliation are still open delivery work.
